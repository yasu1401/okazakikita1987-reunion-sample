# 2026-10-29 認証と会計の実装判断

## 個人のログイン

申込時にメールアドレスと8文字以上のパスワードを登録。同じアカウントで申込確認・個人ページ・思い出アルバムを開く。4桁PINだけでは候補が1万通りで、個人情報を扱う本番の秘密としては弱いため採用しない。パスワード再設定・メール確認は次の工程。

GitHub Pagesのログインは架空データの体験用で、閲覧者がプログラムや保存内容を調べられる。実データを保護する仕組みではない。サーバー版はPHPセッションとサーバー保存のハッシュで本人認証し、申込はuser_idから本人分を取得する。

## 幹事の指定

本人が申込フォームでチェックして幹事になる方式は不可。代表幹事が管理画面で対象者を選び、理由付きで付与・解除する。役割を変えられる代表幹事と、経費・入出金・写真を扱う幹事を分ける。権限は毎回DBを参照し、解除後に管理画面を再読込みすれば拒否する。初回の代表幹事はサーバーCLIで設定。通常画面から代表幹事自身の解除・代表権限の付与はできない。

## 経費と口座

- 立替経費は費目・利用日・支払先・用途・金額・申請者と領収書で管理。
- 申請だけで口座のお金を減らさない。別の幹事が承認し、銀行CSVの出金を確認して経費と照合する。
- 一括の出金を複数経費へ、1件の経費を複数回の出金へ割当可能。明細・経費の未割当額を超える処理は禁止。
- 入金と出金は別の対象へ割当。参加費の入金を経費精算に誤使用しない。
- 取消は元の照合を削除せず無効化し、理由・担当者・前後の状態を保存。
- 口座開始残高＋確認済入金−確認済出金と、未精算経費は別指標。未確認・重複候補・不明入金・不明出金をゼロとして片付けない。

## 次に確定したい業務ルール

1. パスワード再設定・本人確認に使う送信メールと幹事窓口。
2. 代表幹事を誰にするか、幹事の範囲、代表交代の手順。
3. 経費承認を2人で回せるか、領収書がない場合の扱い、承認後の訂正手順。
4. 返金・手数料・寄付等の仕訳、口座開設時の開始残高、締めと確認者。
5. アルバムを見られるのは申込者か入金済者か当日参加者か。現状サーバー版は有効な参加予定者が全クラスと全体写真を閲覧可能。
6. 写真の掲載同意、公開期間、公開終了後の削除・バックアップの扱い。
