# 一斉メール・登録時案内・アルバムへのログイン遷移


## 一斉メールとログイン案内（2026-10-30）

幹事画面「一斉メール」で、件名・本文・対象を指定し、宛先人数と内容を確認して登録します。
既定は全申込者（欠席申請・取消済みも含む）。参加予定者だけにも絞れます。
同一メールアドレスを集約し、不正なアドレスは除外理由を表示します。
問い合わせだけの方は対象外です。確認時の宛先と本文を固定して保存し、
申込者情報が変わった場合は下書きを作り直して再確認します。
登録済みメールの再登録では宛先を増やしません。停止は理由付きで記録します。

開発環境とGitHub Pagesでは実送信しません。PHP版では宛先別の状態・履歴をDB保存し、
公開サンプルはブラウザー内だけに保存します。実際の個人情報は入れないでください。
PHPの `scripts/mail_queue.php` は指定なしで件数表示のみ。
将来のlive設定＋mail_enabled＋明示的な --send のときだけ、問い合わせ返信と一斉メールを
合計最大20件ずつ処理します。Toは1宛先のみで、他の宛先をCC/BCCへ渡しません。
メールサーバー受付済みは到達保証ではなく、処理中・失敗の自動再送はしません。
本番は送信元アドレス、SPF/DKIM/DMARC、定期実行、サーバーの送信制限、迷惑メール判定、
不達・配信到達・大量配信を別途検証してください。今回、実送信やさくら上の試験は未実施です。

参加申込のメール・パスワード欄に、ログイン用であることと幹事のお知らせ先であることを表示。
PHP版はフォトアルバムからログインした後、アルバムへ戻ります。アルバム指定も保持し、
申込確認からのログインは申込確認へ戻ります。戻り先は内部ページの許可リストで制限します。

動作確認：PHPドメイン68項目、HTTP74項目、Node27件合格。
HTTP試験は使い捨てDB・架空データで、ログイン失敗後の行先保持、不正URL拒否、
一斉メールの対象確認・登録・重複防止・停止、開発環境で送信拒否、再起動後の永続化を確認。
